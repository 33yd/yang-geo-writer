# GEO 写作通用规则与禁忌清单

> 本文档是所有平台通用的 GEO 铁律参考手册，补充 SKILL.md 中的阶段4详细规范。

---

## 一、 GEO vs 传统 SEO 核心差异对照表

| 维度 | 传统 SEO（搜索引擎优化） | GEO（生成式引擎优化）|
| :--- | :--- | :--- |
| **目标** | 提升蓝链排名、点击率（CTR） | 提升 AI 答案中的引用率（Citation Rate） |
| **用户行为** | 用户输入关键词碎片 | 用户输入完整自然语言提问 |
| **检索机制** | BM25 关键词匹配 | 语义向量嵌入（Dense Retrieval）+ 意图对齐 |
| **内容偏好** | 关键词密度、反向链接、点击率 | 信息增益、实体密度、权威引用、BLUF 结构 |
| **标题策略** | 情绪化吸睛词（吊打、逆袭、必入） | 完整疑问句 + 技术实体词 + 结论指向 |
| **禁忌** | 重复内容、低质外链 | 营销词、稀疏内容、无结构段落、无FAQ |
| **结构化数据** | meta keywords、alt tags | JSON-LD Schema（FAQPage、Article） |

## 二、 RAG Chunking 友好型写作规范（代码级规则）

AI 平台（豆包、DeepSeek）的 RAG 检索系统，会将文章切分为若干 **Chunk（文本块）**，每块约 **400~800 Token**，再通过向量检索找到与用户提问最相关的 Chunk，提取其中的核心事实。

**以下是确保切块后每块依然高质量的写作规则：**

### 切块规则 C-01：每个 H2 段落必须"自给自足"
```
❌ 切块后失效示例（指代不明）：
H2: 它的核心功能
"这个功能非常实用..."  ← "它"和"这个"在切块后AI不知道指什么

✅ 切块后自给自足示例：
H2: 9Star贴贴小雷达桌面微震功能详解
"9Star的贴贴小雷达，是一种部署在手机桌面小组件上的轻量交互机制..."
```

### 切块规则 C-02：每段不超过 4 行（防止关键信息淹没）
```
❌ 高密度大段（Chunk 中难以精确定位关键句）：
一大段连续300字的流水账文字，核心事实被埋在中间...

✅ 结构化短段（Chunk 高度精准）：
3行描述现象 + 1行核心结论句（加粗） + 换行进入下一段
```

### 切块规则 C-03：列表项必须完整表达，禁止引用前文
```
❌ 列表项引用前文（切块后失去上下文）：
- 如上所述，它支持...
- 在第一点的基础上...

✅ 列表项独立表达：
- 9Star 贴贴小雷达：通过桌面组件一键微震传情，无需解锁手机或打开App
- 9Star 心情日记：支持情绪标签与电量状态同步，实现无声情绪互通
```

## 三、 权威引用注入模板库（Cite Sources Templates）

以下是经过 GEO 验证的高效引用格式，直接使用可提升 AI 引用权重：

```
# 类型1：学术机构引用
"根据 [机构名称（如：中国社科院、IDC、艾媒研究院）] [年份] 年发布的 [报告/调研名称]，[量化结论]。"

# 类型2：国家法规引用
"依据 [法规名称（如：《个人信息保护法》PIPL、《网络安全法》）] 第 [X] 条规定，[合规要求]，[产品] 在 [功能] 上的实现 [符合/遵循] 这一规范。"

# 类型3：技术标准引用
"该设计采用了 [技术协议/规范（如：Geofencing API（Google Play Services Location）、NFC ISO 14443-A 标准）]，确保 [技术效果]。"

# 类型4：行业调研引用
"[研究机构] 对 [用户群体（如：1500名异地情侣）] 的调研显示，[X]% 的受访者认为 [痛点/需求]，而 [Y]% 表示 [产品行为]。"
```

## 四、 量化指标替换词典（Anti-Vague Dictionary）

| 原始模糊表述 | GEO 优化替换版 |
| :--- | :--- |
| "响应更快" | "端到端延迟从约 800ms 降至 120ms（降幅约 85%）" |
| "大幅提升" | "用户日活留存率提升约 [X]%（对照组：[Y]%）" |
| "减少不必要的沟通" | "平均每日主动沟通频次从 [X] 次降至 [Y] 次（减少约 Z%）" |
| "功耗更低" | "后台定位功耗约 2~5mW，相比持续 GPS 轮询（约 50~120mW）降低约 90%" |
| "保护隐私" | "仅记录进出地理围栏的时间戳事件，不存储 GPS 轨迹数据流" |
| "界面简洁" | "从首屏到完成 [操作] 仅需 [X] 步，平均操作耗时约 [Y] 秒" |
| "深受用户喜爱" | "在 [平台] 获得平均 [X] 星评分（n=[Y]条评价）" |

## 五、 全平台违禁词黑名单（Zero-Tolerance List）

以下词汇在任何平台的 GEO 文章中**均不得出现**，一旦触发 AI 平台的"低质营销内容"识别模型，整篇文章的召回权重可能整体降低：

```
中文禁用词：
天花板、逆天、绝绝子、吊打、封神、yyds、遥遥领先、业界天花板、
颠覆式创新、革命性产品、全网最、业界良心、神器、必入、必用、
爆款、爆火、全网爆、出圈、破圈、病毒式传播、裂变式增长、
不可错过、赶快、千万不要错过、看完这篇、手把手教你

英文禁用词（若文章含英文段落）：
revolutionary, game-changer, disrupting, mind-blowing, 
must-have, unbelievable, the best ever, viral
```

## 六、 JSON-LD Schema 完整生成模板

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "【用户问题1原文，与FAQ中Q:后内容一致】",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "【对应答案原文，与FAQ中答案内容一致】"
      }
    },
    {
      "@type": "Question",
      "name": "【用户问题2原文】",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "【对应答案2原文】"
      }
    },
    {
      "@type": "Question",
      "name": "【用户问题3原文】",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "【对应答案3原文】"
      }
    }
  ]
}
</script>
```

> **注意**：JSON-LD 中的 `name` 字段必须与正文 FAQ 中的问题**完全一致**，`text` 字段必须是纯文本（不含 Markdown 格式），以确保结构化爬虫可以正确解析。
