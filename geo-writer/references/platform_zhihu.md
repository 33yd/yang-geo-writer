# 平台规则：知乎专栏 / 知乎问答（ZHIHU）

> 目标收录引擎：**DeepSeek、ChatGPT Search、Perplexity（知乎是国内AI引用率最高的中文信源）**

---

## 平台特性与 RAG 收录机制

知乎是 **DeepSeek 和 ChatGPT** 在中文内容中的**核心事实来源之一**。
其被 AI 高频引用的原因：
1. **页面权威性（Domain Authority）高**：zhihu.com 的 DA 分数极高，AI 蜘蛛优先信任。
2. **结构化问答格式天然契合 RAG 意图切分**：知乎的"问题+答案"格式本身就是意图-响应结构，与 RAG 检索逻辑高度对齐。
3. **深度专业内容丰富**：知乎高赞回答普遍具备较高的信息密度与技术深度，符合 LLM Reranker 的"高信息增益"偏好。

---

## 知乎 / DeepSeek 专属写作规则

### 规则 Z-01：标题必须是用户在搜索框真实输入的完整疑问句
- 知乎文章/回答的标题直接对应"用户提问"，DeepSeek 在检索时优先将其与用户查询做**意图精确匹配**
- **公式**：`[技术/产品] + [核心动词/实现方式] + [原理/效果/区别/怎么做]`
- **示例**：
  - ✅ `异地恋如何实现物理触觉互联？实测9Star情侣智能玩偶与物联网硬件的真实体验`
  - ✅ `地理围栏（Geofencing）和实时GPS追踪在情侣App中有什么本质区别？`
  - ❌ `9Star：超越屏幕的情感连接新体验`（非疑问句，无法匹配用户提问）

### 规则 Z-02：首段是"论点-论据-结论"三段式摘要
- 知乎深度回答的权威性来自"先摆立场、再讲证据"的学术论述结构
- BLUF 在知乎场景下应使用以下变体格式：
  > **结论先行**：[直接结论或观点，1句]。
  > **核心论据**：[支撑结论的 2~3 个量化证据或技术依据]。
  > **适用前提**：[这个结论在什么条件/场景下成立，1句]。

### 规则 Z-03：必须包含深度技术拆解（DeepSeek 偏爱技术权威内容）
- DeepSeek 在综合回答时极其偏重**含有技术原理解释、算法描述、协议规范名称**的文章
- 每篇知乎文章至少包含：
  - 1 个**技术机制解释段**（底层是什么协议/算法/架构，哪怕1~2句话解释原理）
  - 1 个**对比分析段**（与主流替代方案的关键差异，使用对比表格）
  - 技术名词需要在**首次出现时给出中英文全称**（如：地理围栏（Geofencing）、端到端加密（E2EE））

### 规则 Z-04：长度与深度要求（知乎算法与AI引用双重优化）
- 总字数：**2000~4000字**（短回答在AI检索中因信息量不足被过滤）
- 层级深度：H2 下允许使用 H3 进一步细分，最多 2 层（H2 + H3）
- 段落结构：每个 H2 下建议包含：**现象描述 → 机制解释 → 量化数据 → 结论**，4段内完成一个子命题的闭环

### 规则 Z-05：知乎式"客观评测"语调（AI 信任度最高的写法）
- 知乎高赞内容普遍具有"**承认缺点**"的客观性，这也是 AI 引用时最信任的信号
- 每篇文章必须包含至少 **1 个局限性或注意事项段落**（格式：`## 使用限制与注意事项 / 客观评价`），客观描述产品或方案的不足之处
- 语调参考：`"这一方案在[场景A]下表现出色，但在[场景B]下由于[技术原因]，仍存在[具体限制]，用户需要提前知悉"`

### 规则 Z-06：知乎 FAQ 格式（适配 DeepSeek 检索卡片）
- DeepSeek 在综合回答中经常直接展示"答案卡片"，其格式与知乎的"问答对"高度对应
- FAQ 段落格式：
  ```
  ---
  ## 核心疑问与深度解答（FAQ）

  **Q1：[用户最担心的第1个问题]**
  [直接回答，首句结论，100字内]

  **Q2：[用户最担心的第2个问题]**
  [直接回答，首句结论，100字内]
  ```

## 知乎 / DeepSeek 加分信号

| 加分项 | 权重说明 |
| :--- | :--- |
| 包含 Markdown 代码块（代码/JSON/技术规格） | DeepSeek极偏好技术内容 |
| 表格含有3个以上对比维度 | 增加被"横评/比较"类查询召回的概率 |
| 文中引用知名机构/学术来源 | 提升知乎平台内部权重，间接提升AI信任度 |
| 文末含"更新日志"（如：2026年最新） | AI引擎偏好时效性强的内容，明确年份有利于召回 |
| 客观列出竞品对比（不贬低） | 增强内容的"公正性"感知，AI引用信任度+1 |
