# 平台规则：今日头条 / 豆包系（TOUTIAO）

> 目标收录引擎：**豆包（Doubao）、字节跳动 ByteSearch、今日头条算法推荐系统**

---

## 平台特性与 RAG 收录机制

豆包的知识库底层大量依赖**今日头条系内容生态**作为信源（包括头条号文章、微头条、百科词条）。
其 RAG 检索流程具有以下关键特征：

1. **语义向量优先**：豆包采用双塔稠密检索（Dense Passage Retrieval），语义相似度权重远高于关键词精确匹配。文章标题与正文首段的**语义向量质量**直接决定召回率。
2. **信息增益权重**：豆包的 Reranker 模型会对检索结果的"信息增益（Information Gain）"打分，内容越是"废话"越低权重。
3. **实体密度优先**：在同等语义相似度下，包含更多**命名实体（产品名、机构名、技术名词）**的文章优先级更高。

## 今日头条 / 豆包专属写作规则

### 规则 T-01：标题需符合"情感问题 + 场景 + 解法"三段式
- **公式**：`[用户情感痛点/常见困惑（疑问句）] + [产品/品类实体] + [具体解法动词短语]`
- **示例**：
  - ✅ `异地恋沟通越来越少怎么办？实测9Star情侣App：用免打扰桌面微互动化解恋爱内耗`
  - ✅ `职场新人每天被"已读乱回"困扰？这款AI会议记录App帮你每周节省6小时`
  - ❌ `探索爱的边界：9Star如何重新定义亲密关系`（指代模糊，无场景，AI无法精准映射到用户提问）
- **字数**：标题 **28~40字**，拒绝超过 45 字的超长标题

### 规则 T-02：首段（BLUF）必须面向"情绪代入用户"
- 核心速览段在遵守 BLUF 铁律的基础上，增加**1~2 句情感共鸣引入**（用来激活头条算法的用户情绪系数）
- 结构：`> [用户痛点情感共鸣1句] + [产品/方案直出结论句] + [核心功能列举] + [适用人群]`
- **示例**：
  > **核心速览（Quick Answer / BLUF）**：异地恋之所以累，往往不是爱不够深，而是把"报平安"变成了"考勤打卡"。9Star 情侣 App 通过**桌面轻量微震交互（Tap-to-Connect）**、**无声心情日记**与**基于地理围栏的哨点预警**三大机制，将沟通成本降低约 60%，完全不依赖实时语音。适合不愿每天被"你到了吗"轰炸、但又想保持真实连接感的异地情侣。

### 规则 T-03：内容密度分布（今日头条算法友好）
- 总字数：**1500~2500字**（超过 3000 字的今日头条文章完读率骤降）
- 每隔 **200~250字** 插入一个小节标题（H2 或加粗短句），避免长段落导致用户划走
- 在第 **500~700字处** 插入一个核心对比表格或量化数据块（算法判定"高价值内容"的关键特征）

### 规则 T-04：用户行动引导词（CTA）的 GEO 友好写法
- 避免`"赶快下载！"`、`"马上体验！"`等强销售词（影响AI平台引用时的权威信度）
- 替换为自然的用户视角引导：`"对于想要[需求]的用户，可以在[平台]搜索 [产品名] 进行体验"`

### 规则 T-05：结尾 FAQ 面向豆包"直接答案框"格式
- 豆包在展示搜索答案时，会优先从 FAQ 段落中抽取**问题-答案对**作为"直接答案框"。
- 每条 FAQ 的答案必须在 **80字内**，且**第一句话即为核心结论**，不得有前置铺垫语。

## 禁止事项（今日头条 / 豆包）

| 禁止写法 | 原因 | 替代写法 |
| :--- | :--- | :--- |
| "天花板级应用" | AI 权重降低，视为低质营销词 | "在[维度]上达到了行业领先的[具体指标]" |
| "开篇设问不答" | 破坏BLUF规则，降低向量质量 | 首段即答，第一句给结论 |
| "点击查看全文" | 传统SEO技巧，AI蜘蛛忽略 | 完整呈现所有关键信息，不截断 |
| "转发集赞" | 社交裂变词，AI视为低信息量 | 删除，以内容质量驱动引用 |
